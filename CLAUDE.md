## Project Overview

Python library (`govee-local-api`) for communicating with Govee smart light devices over the local network using UDP multicast. Used as a dependency by the Home Assistant Govee integration. Published to PyPI.

## Build & Development

Uses **uv** for dependency management (`uv.lock`, `uv_build` backend). Python >= 3.11.

```bash
uv sync                                  # Install dependencies (incl. dev group)
uv run pytest                            # Run all tests
uv run pytest tests/test_message.py      # Run a single test file
uv run pytest -k test_scan_message       # Run a single test
uv build                                 # Build package
```

```bash
pre-commit run --all-files                   # Run all pre-commit hooks
```

## Architecture

The library is a pure asyncio UDP protocol implementation with no external runtime dependencies.

- **`controller.py`** — `GoveeController(asyncio.DatagramProtocol)`: Main entry point. Manages device discovery via UDP multicast (239.255.255.250), periodic status polling, and device eviction. Sends commands to devices on port 4003, listens on port 4002, broadcasts discovery on port 4001.
- **`device.py`** — `GoveeDevice`: Represents a single Govee light. Holds state (on/off, brightness, color, temperature), exposes the model's Kelvin range as `temperature_range` (falling back to the default range when the device has no capabilities) and exposes async control methods that delegate back to the controller.
- **`message.py`** — Message protocol. `GoveeMessage` is the base class; subclasses handle specific commands (`ScanMessage`, `OnOffMessage`, `ColorMessage`, `BrightnessMessage`, etc.). `PtRealMessage` handles binary commands with XOR checksum encoding via base64. `MessageResponseFactory` parses incoming JSON messages into typed response objects. `ColorMessage` clamps white temperatures to the range it is given, falling back to `DEFAULT_TEMPERATURE_RANGE` imported from `light_capabilities` — the message layer keeps no Kelvin constants of its own.
- **`light_capabilities.py`** — Device capability registry. `GoveeLightCapabilities` defines what features a device model supports (RGB, color temperature, brightness, segments, scenes) and its Kelvin `temperature_range` (`GoveeTemperatureRange`, defaulting to `DEFAULT_TEMPERATURE_RANGE` = 2000-9000 K — the single source of truth for the default range, also used by `ColorMessage`). `GOVEE_LIGHT_CAPABILITIES` is the dict mapping SKU strings to capabilities. New device support is added here. Entries carry no scenes: at import `_with_model_scenes()` replaces every entry's scenes with that model's set from the packaged `data/model_scenes.json` (models missing from it get none), sharing one capabilities object between models with the same base capabilities and scene set.
- **`device_registry.py`** — `DeviceRegistry`: Internal store of discovered devices and a queue for manually-added device IPs.

## Adding Support for New Devices

To add a new Govee device model, add an entry to `GOVEE_LIGHT_CAPABILITIES` in `src/govee_local_api/light_capabilities.py`. Use `create_with_capabilities(rgb, temperature, brightness, segments, temperature_range=None)` or reference `BASIC_CAPABILITIES` for standard devices — don't pass `scenes`, the registry's scenes come from `model_scenes.json`. Then run `uv run python scripts/generate_model_scenes.py` to fetch the new model's scenes (by default it only touches models added to or removed from the registry; a test fails if you forget). The segments parameter is the number of individually controllable LED segments. Pass `temperature_range=(min_kelvin, max_kelvin)` only for models whose white range differs from the 2000-9000 K default; `ColorMessage` clamps to the device's range.

`src/govee_local_api/data/model_scenes.json` (generated data lives in the package's `data/` folder, apart from code) is generated by `scripts/generate_model_scenes.py` (by default it compares `GOVEE_LIGHT_CAPABILITIES` with the file, fetches only the added SKUs and drops removed ones; `--all` refetches every SKU, `--skus ...` the given ones; writes nothing if any fetch fails) from Govee's per-model scene library (`app2.govee.com` light-effect-libraries, one request per SKU with an `AppVersion` header): the firmware scenes only — `sceneType` 0 without a `scenceParam` blob, so each code is one byte `SceneMessages` can play — keyed by scene key — Govee's name in snake*case (`snow_flake`, `blue_sky_white_clouds`), a valid Home Assistant translation key (`[a-z0-9-*]+`) so the HA integration can use it as the effect value as-is — (variant letters only appear where they tell two kept scenes apart: an effect's variant letter is appended only when two or more variants of a scene are kept — `rainbow`, not `rainbow a`, when variant B needs a blob — and a letter ending Govee's own name, like `Aurora B`(the firmware twin of a blob-only`Aurora`), is dropped unless a kept scene already has the bare name, like `shiny`next to`shiny b`; a name collision fails generation), stored as shared scene sets (`{"sets": {id: {name: code}}, "models": {sku: id | null}}`—`null`for a model checked and found to have no firmware scenes, so the file lists every registered model; set ids hash their contents so unchanged sets keep their ids). Never edit it by hand. The same run writes`ha_scene_names.json`in the repo root (not packaged):`{scene key: display name}` in Govee's casing (`"snow_flake": "Snow flake"`), for the effect states in HA's `strings.json`; incremental runs merge into it, and it must exist (create it with `--all`). The fetching and filtering live in `scripts/fetch_scene_library.py`, which also dumps the full library and a scene→devices index for analysis (`--model-scenes-only` rebuilds the packaged file from such a dump without fetching).

`SUPPORTED_DEVICES.md` is auto-generated from the registry by the `generate-supported-devices` pre-commit hook (`scripts/generate_supported_devices.py`) — never edit it by hand.

## Key Conventions

- Version lives only in `pyproject.toml` (bump with `uv version --bump <part>`); `__version__` reads it from the installed package metadata
- Tests are in `tests/` and use plain pytest (no fixtures framework)
- `pythonpath = "src"` is configured in pytest settings — imports use `govee_local_api.*`
- CI tests against Python 3.11, 3.12, and 3.13
